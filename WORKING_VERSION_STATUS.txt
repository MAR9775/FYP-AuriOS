1. WHAT AURIOS IS
--------------------------------------------------------------------------------
AuriOS is a Windows desktop AI assistant (Electron + Python) that automates
setting up a dev environment — installing software, fixing PATH, creating
Python venvs — through a natural-language chat interface. It also has a
full Admin Console for user/software/system management.


2. VERIFIED WORKING (tested live on 2026-07-24)
--------------------------------------------------------------------------------

  [OK] Electron shell launches, window opens, no crash/Traceback in logs/aurjos.log
  [OK] SQLite (aiosqlite, WAL mode) reads/writes preferences without error
  [OK] Clean shutdown sequence (DB connections closed properly)

  KNOWN GOTCHA — must run with the project's .venv, not system Python:
  electron/main.js spawns the backend with the bare command "python -m uvicorn
  backend.server:app ...". If the machine's system-wide "python" resolves to a
  different install (as it did here: FastAPI 0.104.1 + Starlette 1.3.1, an
  incompatible pair), the backend crashes on boot with:
      TypeError: Router.__init__() got an unexpected keyword argument 'on_startup'
  Fix: put .venv\Scripts on PATH before "npm start" (or hardcode the venv's
  python.exe path in main.js) so it uses the pinned versions below.

4. AGENTS — 6 total, all extend BaseAgent (ReAct: Reason -> Act -> Observe -> Decide)
--------------------------------------------------------------------------------
  Orchestrator (backend/core/orchestrator.py) runs these in sequence for every
  install request, coordinated as a 7-stage pipeline:

  1. DetectionAgent   — checks Windows Registry + PATH for already-installed software
                         (skips anything already present)
  2. DownloadAgent     — fetches installer .exe/.msi files from the AuriOS GitHub
                         Releases repository
  3. InstallAgent      — runs silent installs (e.g. /VERYSILENT), local installer
                         first, winget as fallback
  4. ConfigureAgent    — writes installed tools into the user's PATH via registry,
                         broadcasts WM_SETTINGCHANGE so it takes effect immediately
  5. ValidationAgent   — re-runs detection to confirm the install actually succeeded
  6. EnvironmentAgent  — scaffolds a project folder + Python venv on request
                         (+ a final "Launch Step" pops open GUI tools like VS Code —
                          not a separate agent class, just the pipeline's last step)

  Intent routing (backend/llm/intent_parser.py) is rule-based first (regex/keyword
  match against a fixed vocabulary of presets: python_basic, python_ml, web_dev,
  full_stack, data_science, java, single_software, database_clarify, greeting,
  help, thanks, goodbye, unknown) — Ollama is only called for conversational
  replies or genuinely unclear input, since small local models can't reliably
  emit a strict JSON enum.

  Core:     /chat, /history, /ping, /system-status, /system-status-full,
            /profile, /preferences, /installation-history, /speech/transcribe
  Admin:    /admin/stats, /admin/users, /admin/sessions, /admin/installations,
            /admin/conversations, /admin/preferences, /admin/accounts (+ reset-password,
            revoke, deactivate/reactivate), /admin/dashboard-stats, /admin/system-status
  Auth model: Bearer token + server-side role check (_require_admin), 5 failed
  logins per IP / 300s triggers a 60s lockout (429).
